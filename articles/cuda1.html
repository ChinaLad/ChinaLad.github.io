00_INTRODUCTION

The GPU isn't reserved only for video game developers and local LLMs to use as they please. As the owner of the GPU, you can use it as you like, just like you use your CPU when programming. The main question is how to make the GPU execute code, and what are the tasks in which it exceeds. In this and the following articles about CUDA, we will see what the GPU is and how to use it to compute stuff very quickly.

01_GPU_ARCHITECTURE_&_TERMINOLOGY

Many articles and tutorials spend a lot of time explaining the key concepts, but I'll go quickly through them and with each new example and diagram things will become clearer and give us a fuller picture.

  • Host is the CPU & its memory.
  • Device is the GPU & its memory.
  • Kernels are functions declared with __global__ launched by the host and executed across thousands of device cores.

We mentioned parallelism, and in CPUs, parallelism introduces concepts like threads and processes. Some of these concepts are key for GPUs. The smallest units of programming for GPUs are threads, and they are further organized into larger structures.

  • Warp is a sequence of 32 consecutive threads. They share the same instruction pointer, so an instruction aimed at a thread is sent to the whole warp.
  • Block is a 1/2/3D set of threads. The dimensions help with kernel development since some task naturally work with 2D (matrices, images), or 3D grids (videos, 3D textures).
  • Grid is a 1/2/3D set of blocks.

The concepts above also dictate data movement, but that will be discussed later.

The GPU is like a CPU specifically developed for performing many simple computations in parallel. Multiple cores share L1 Cache, the cores are simpler and specialized for calculations, and more.

>> INFO GPU cores are so simple that even branching using if's doen't work like in CPUs. All branches are computed by splitting the cases across multiple threads.
